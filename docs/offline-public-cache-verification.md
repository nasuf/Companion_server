# 活动推荐公共检索复用（2026-10-08）

## 复用边界

仅缓存公共地点事实、公共公告的结构化提取与已验证的地点图片。
用户画像、记忆、近期去过的地点、推荐文案与旅途素材不进入公共缓存。

地点查询将设备位置映射到 0.01 度网格中心，使同一区域的小幅 GPS
变化复用同一查询。搜索范围包含网格余量；拿到结果后仍用每位用户的
真实位置计算距离，并重新执行城市、类别与个人历史过滤。
这是一层短期查询缓存，不是维护全国地点库。

| 内容 | 有效期 | 额外规则 |
|---|---|---|
| 原生 POI 检索 | 30 分钟 | 空结果 45 秒 |
| 公共网页检索/读取 | 3 分钟 | 接受/到达时强制独立读取最新公告 |
| 公告模型提取 | 3 分钟 | 空结果 30 秒；原文、日期、Web 提示词内容变化使缓存失效 |
| 地点图库填充 | 15 分钟 | 无图 60 秒；每次命中检查 POI 身份和本地文件存在性 |
| 已完整持久化图库 | 沿用现有 7 天 | 保留真实图片；部分图库在短期复用期后继续尝试补充 |

公告提取缓存不保存“现在可用”判断；每次调用按当前时间重新校验。
临时活动接受/到达时仍保留取消、改期和举办场所检查。

同一查询的并发缺失请求在进程内合并，并通过 Redis 带令牌租约协调
不同 worker。请求有时限，失败不缓存；一位用户取消请求不会取消其他
用户正在等待的公共查询。Redis 缓存不可用时助手层退化为本进程加载，
提供方原有速率限制仍生效。

## 图片成本

仅对已选定的候选补充资料/补图。先尝试该地点的原生照片，足够三张时
跳过补图网页读取与图片搜索；不为了省调用而放松图片绑定、去重、像素
校验，也不仅因原生照片为空就提前替换模型选择的地点。
保持原有规则：全部无图才可考虑同类别替代；已有部分图片与临时活动
保持原地点/场次。

## 验证

- `test_offline_public_cache.py`：并发合并、取消隔离、失败恢复、JSON
  损坏、独立 fresh 读取、城市/网格/类别隔离、公告过期、原文和 Web
  提示词变化导致提取缓存失效。
- `test_offline_public_cache_e2e.py`：两个独立 Python 进程连接真实 Redis，
  两个请求都成功，公共加载计数恰好为 1，租约释放后没有遗留锁。
- `test_cleversee_activity_e2e.py`：附近 GPS 重复查询的 SDK 调用次数保持
  1；个人近期地点仍被过滤。不同用户重新生成文案、复用同一图库时不
  增加外部调用。0/1/3 张图库均复用，文件丢失后重新获取并修复。
- 保留真实 HTTP、PostgreSQL、Redis、图片解码/去重、活动接受/到达/
  归档，以及 Flutter 调用后端的 E2E。

重跑需要独立本地 `companion_proactive_e2e` 数据库和 Redis，通过
`PROACTIVE_E2E_DATABASE_URL`、`PROACTIVE_E2E_REDIS_URL` 传入；不可指向生产。
Flutter E2E 另设 `OFFLINE_FLUTTER_E2E=1` 与 `OFFLINE_FLUTTER_PROJECT`。
外部模型/供应商使用固定响应测试调用数量和失败路径，真实供应商抽查
不能代替这些确定性验证。本次没有 registry 提示词内容修改。

本地真实 CleverSee 抽查（镇江咖啡馆、博物馆两类）：首次 SDK 2 次、
4.914 秒；同网格小幅移动 GPS 后再次查询 SDK 0 次、0.009 秒。
咖啡馆两次均有 12 个符合条件的地点，博物馆原生查询为空；此抽查只
测传输缓存，不替代发现流程的备用查询，也不代表所有区域的命中率。
