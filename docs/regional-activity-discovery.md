# 按用户区域实时发现活动（2026-10-06）

## 原因

旧实现有类别列表，但默认从列表头开始搜索，并只取每类第一个关键词。图书馆/博物馆容易反复命中，书店、小吃和临时活动缺少独立机会。结果窗口只留六个来源，且把合集当成无效地点整体丢掉；品牌没有“店/馆/园”后缀也容易被拒绝。图库先截取来源再匹配地点，导致后排候选的真实照片被漏掉。

真实搜索还发现企业黄页被当成地点、导航文本被当成地址，以及标题分隔符格式变化把城市后缀拼进咖啡店名字。这些情况已加入回归验证。

## 方案与边界

不建立全国地点库。每次以用户当前位置的城市和区县实时检索，复用现有 Tavily 的公开索引；既有公共地点表只缓存已验证的照片，不从中抽取活动候选。搜索结果缓存一小时，公共照片缓存七天，个人记忆和推荐文案不进入共享缓存。无需新增地图商用 key 或其他付费服务；仍会使用现有 Tavily 额度，不能把它描述为无限免费搜索。

流程为：区域和类别规划 → 搜索发现 → 候选池 → 来源/地点/日期核实 → 多样性排序 → 图片补全 → 同一活动记录提供卡片、详情和回忆。

- 27 个检索意图覆盖咖啡、茶室、展览馆/画廊、博物馆、图书馆、独立/旧书店、公园、水边、轻户外、老街、夜市、苍蝇馆、小吃、面馆、甜品、手作、花艺、旧物、唱片、演出、运动、科普及临时活动。类别是开放的检索方向，不是场所白名单：有明确名称、来源事实和可访问地点的其他场所也可进入候选。
- 用户兴趣、最近二十条推荐、用户/工作空间种子共同决定顺序。类别和同类关键词轮换，跨类别家庭轮换；不把某个兴趣扩展成每个场所都有的设施。
- 先搜索区县/街道，候选不足时使用城市补搜。实际地址保留；无法证明距离时不输出“就在你附近”之类承诺。Flutter 优先使用区县信息，并请求中文地理名称；平台不支持语言覆盖时继续定位，不影响 GPS。
- 至少探索三个查询批次，每批两条；最多十二条发现查询，总预算四十秒。提前完成的来源立即保留，不能被同批慢请求一起丢弃。达到四个不同场所且至少两个类别家庭后可停止。
- 模型返回最多六个候选；兼容旧 Web 版本的单卡 JSON。模型十八秒超时或输出无效时，由可验证的单地点来源生成候选。模型提取合集中的具体名称，规则提取明确名称字段/章节标题，最多三个线索独立搜索，十秒总核实预算。未出现在来源中的模型名称不能触发核实；合集本身不能成为地点。
- 名称保留分店，裸品牌不擅自对应到另一分店。单独来源必须绑定名称及城市，不能只因域名可信就采信。地址重新从核实来源读取，不沿用模型地址；过滤黄页标题、工商注册信息和网页导航。店名没有通用后缀时，明确名称字段、品牌、餐饮/小吃名称及地址证据可以支持它。
- 临时活动必须有明确举办场所和带年份的日期；能识别时段时校验具体结束时间。过期、缺年份、错误日期或不完整日期范围不推荐，也不将其改成长期地点。只考虑未来三十天内开始的活动，过期时间不晚于来源结束日期；长期地点仍保持原有十四天有效期。
- 排序先考虑区域、最近类别重复和兴趣，再考虑已绑定页面的照片证据。事实来源与摄影来源保留可追溯信息；未知地址/开放安排不编造。
- 图库先按选中地点筛来源，再限制数量。目标为三张不同实景图；门头、店内、吧台、书架、摊位等场景也支持，明确指向其他场所的图注拒绝。继续拒绝没有独立地点证据的查询级混合图片、图标、广告、规划图及未验证图片，检查公网地址、跳转、类型、像素、大小和近重复。
- 最多尝试三个有效场所，图库共享五十五秒预算；保留已有可靠照片，优先更完整的图库。没有图片证据时保留真实地点，不因照片缺失制造“未授权定位”错误，不用无关图凑三张。详情文案生成十五秒超时保留来源兜底。

外部索引不保证覆盖所有商家、临时活动或所有图片。被登录墙挡住的小红书/点评页面不会被绕过。真实网络抽查存在来源超时及只获得一张图片的咖啡店；这属于剩余覆盖限制，不能用自动化通过宣称所有真实地点永远有三张图。

## 2026-10-07 图片通路修复与豆包接入结论

当前图片缺失主要是适配器和证据规则问题：独立 `images` 数组被丢弃；原生 `alt` 为「内饰／美食」时也被要求包含完整地点名；简体「悠澜咖啡」与繁体「悠瀾咖啡」无法匹配。以上问题已修复。

- 分开保留网页内照片与独立搜图文档。独立图片需要自己的索引标题同时识别城市、地点；不能以搜索 query 或模型生成的场景描述给任意图片赋予地点。没有来源网页 URL 时保留为空，记录索引标题、查询和图片 URL，不伪造来源。
- 已核实的单地点页面支持原生场景图注、响应式 `srcset` 与常用懒加载字段；不要求每张「门头／内饰／美食」再次写出店名。广告、菜单、图标、效果图、其他明确场所仍拒绝。
- 用 OpenCC 在匹配阶段归一化简繁，允许城市名可选「市」；展示名称、地址及 URL 不改写。不使用宽泛模糊匹配，来源中明确的其他分店不能借用目标品牌身份。
- 首次补图查询使用城市＋具体地点，避免完整街道地址压低召回；第二次才加地址细化。按来源交错、最多三路并行下载，每轮最多十八次尝试；继续保留 35 秒图库预算、下载大小／像素／近重复／公网跳转校验。缓存版本升为 v4，防止沿用漏掉独立图片的搜索缓存。
- 保留下载、候选、重复、不可用等阶段计数，排查空图时区分索引无结果、证据拒绝及 CDN 不可下载。无可靠图片仍不伪造照片、不阻止真实地点推荐。

真实生产网络抽查使用修改后的模块在临时解释器中运行，不覆盖生产文件、不创建推荐或聊天记录。镇江博物馆、悠澜咖啡均下载并验证三个不同 JPEG；悠澜咖啡先前为空。扩展抽查中，镇江市图书馆、南山风景区也取得三张；宴春楼、凤凰书城在这次输入和时间预算内仍未取得合格图片。因此不能宣称照片全覆盖，源站封禁、搜索超时、地点别名及图片归属描述错误仍可能影响覆盖。

### 豆包的三条实际请求

现有聊天模型为 `ark/doubao-seed-character-260628`。仅复用现有 Key 做有限请求，没有购买套餐或开通服务。

| 路径 | 实测 | 判断 |
| --- | --- | --- |
| 官方独立搜图 `POST /search_api/web_search`，`SearchType=image` | HTTP 200，业务错误 `invalid_api_key`（700901） | 方舟聊天 Key 目前不能直接用于独立图片搜索 |
| 方舟 Responses，`web_search`＋`sources=["doubao"]` | HTTP 403，`AccessDenied` | 当前账号尚未开通这条豆包搜索能力 |
| 现有方舟联网内容插件 `web_search` | HTTP 200，`web_search_call`＋文本网页引用；没有结构化图片项 | 可以找网页线索，本次不能作为直接图片源；引用的 `logo_url` 是站点标识，不能当地点照片 |

重现脚本：`scripts/probe_offline_image_search.py`。每次至多一个请求、30 秒超时，只输出状态及响应结构，不输出密钥、签名 URL 或模型原文，也不写活动／记忆。

### 最终落地方案

现在使用已修复的 Tavily 多通道搜图和场所证据规则，不新增付费服务。活动发现仍以用户所在区域实时进行，保留咖啡、展览、博物馆、图书馆、书店、公园、苍蝇馆、小吃及临时活动等开放类别，不维护全国地点白名单。公共地点缓存只避免重复搜索。

如后续开通豆包独立搜图并取得正确的搜索 Key，再以 Tavily 图片不足时的补搜源接入，先做同城多类别样本比对，记录可下载数量、实际归属、重复率、时延及调用成本，达到标准再启用；不将目前鉴权失败的路径接入每次推荐重试。官方文档确认 Custom 支持 `SearchType=image`，但 App 的图片数量不能作为 API 覆盖率保证。搜索与聊天、订阅与按量 Key／额度应分别配置和核算。

腾讯地图适合作为将来的地点身份、分店、地址及坐标核实层；Tavily／豆包搜索负责内容、限时活动与图片。地图 POI 返回的坐标也不能证明用户实际到达，手机位置与地点坐标需统一坐标系后校验。接入前需要确认当前账号的商用权限、地点搜索能力和配额，图片继续走独立搜图通路。本次没有开通或假装已接入地图／豆包服务。
