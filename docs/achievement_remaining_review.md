# Remaining Achievement Review

审计日期：2026-06-01

本文件用于继续逐条梳理尚未单独讨论的成就。已单独讨论过的条目暂不重复展开：#5、#17、#27、#40、#42、#59、#62、#64、#73、#87。

全局结论：

- 所有解锁仍以 `user_id + agent_id + achievement_id` 独立去重。
- 统计事件与聚合事件也以 `user_id + agent_id` 为主要维度，跨同一 agent 的多个未删除 conversation 合并，跨用户/agent 不混算。
- Redis 已解锁缓存只在 `repository.unlock_achievement` 统一入口生效，缓存 key 为 `achievements:unlocked:{user_id}:{agent_id}`，不改变任何规则语义。
- “当天/24小时”类统计目前统一按北京时间自然日处理；单次事件型规则不做窗口查询。

## 当前需要产品确认/后续重点看的条目

1. #15、#21：当前是关键词 cue，不是 resolved intent，误触发/漏触发都可能存在。
2. #22：依赖轻量情绪估计器，语义稳定性取决于现有情绪模型。
3. #28：文档说“用户下次登陆弹出”，当前是日终解锁、在线时推送。
4. #44：和 #40 类似是比例类，但尚未设置最低聊天量门槛，极小样本可能触发。
5. #45：标点和 emoji 已计入可见字符数；仅纯空白消息仍可能是 0，需要确认空白消息是否会进入聊天。
6. #56：实现按文档固定 23:00-07:00，不按真实 AI 作息；这和 #48/#74/#93 的真实作息口径不同，但文档本身就是固定时段。
7. #70：名称是“句号爱好者”，条件和实现都是问号，名字/文案可能不一致。
8. #92：逻辑要求 100 条主动消息全部有 3 分钟内回复；如果历史主动消息事件早期没完整记录，老数据可能较难达成。
