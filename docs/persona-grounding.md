# 角色事实归属与地点污染保护（MEMLOC，2026-10-09）

角色档案 `ai_agents` 的姓名、城市、年龄、职业为权威来源。随机日程、历史 assistant 自述和由它们生成的自我记忆不能反向修改档案。AI 侧记忆的拥有者与事实主体是两个概念：“用户向我分享了镇江的位置”仍然是有效互动，不能据此把 AI 放在镇江。

## 已确认根因与修复

原日程生成缺少角色城市，用户 L1 随机个性化又读取身份地点、未过滤归档，并且没有绑定生成 Agent 的 workspace。错误日程进入主动消息与主聊天当前状态，再经 AI 自我抽取和每日总结固化。原类别保护只限制身份/偏好等类别，“我本来住镇江”被归为生活/居住后绕过保护。这些路径在 LangGraph 迁移前已经存在。

- 日程始终读取生成 Agent 的真实档案，只借用同 workspace 未归档的用户兴趣。生成和读取旧缓存都验证可能涉及实际地点的活动；原始旧日程保留为证据，拒绝的活动用通用文案替代，时间、忙闲和睡眠不变。
- 主聊天（legacy、LangGraph）、分级回复及主动消息均添加同一个角色事实上下文。回复交付前验证可疑地点，聊天、短路、TTS 用同一纠正文案；主动消息验证失败则跳过，记录 skip reason。延迟解释也校验。虚拟陪伴的“我在这儿陪你”不等于实际到场；危机照护地点校验失败时保留既有安全照护兜底，不能改成无关的地点道歉。
- AI 生成稳定身份事实不得借生活/情绪类别写入；生成地点由精确 workspace 对应 Agent 校验。记忆合并后的新文案也经过相同保护。用户记忆和可信人设种子不受该生成保护拦截。
- 校验服务不可用、超时或输出不完整时，不放行可疑宣称。记忆写入抛出可重试错误，水位线不前进；明确无效内容才有意拒绝并消费。正常非地点回复不增加模型调用。

## 校验模型、延迟与边界

使用 `get_grounding_model()`；DashScope 默认 `PERSONA_GROUNDING_MODEL=qwen3.5-plus`，temperature=0、单次最多 50 项、每项 4000 字、总调用最长 5 秒。其他提供商保留原 utility 路由，需要针对该模型另行校准。轻量 flash 在真实校准中有主语、计划和地点误判，不能据其 mock 单测通过宣称生产正确。

只对可能有地点含义的条目调用语义校验。日程先筛出可疑条目、批量一次验证；成功校验的派生读取缓存最长 24 小时，档案、日程或当前 Web 校验提示词内容变动立即换 key。校验失败仅缓存通用活动 5 分钟，保留重试机会；禁用或无法读取当前校验提示词时不复用旧判定。这样后台频繁读取日程不会每 5 分钟重复调用模型。普通“我在吃饭/工作室处理工作”等不增加调用。风险回复额外增加模型延迟；不可用时会减少主动输出或返回简短纠正，属于明确的保守取舍。

在独立旅行业务尚未提供可信地点事件之前，历史自述和随机日程不能证明 Agent 跨城旅行。新增具体街道/公园等专名没有档案依据时也不声称亲历；泛指在家/公司/附近可以。未来若增加真实授权旅行，需要单独设计可信事件来源，不能取消主体边界。

这不是对所有自然语言幻觉的数学保证。当前保护针对已确认的位置/身份污染链路；地点变体、不同模型、提示词人工修改仍需持续评测。Trace 将显示“角色地点事实校验”及一致/拦截结论。
