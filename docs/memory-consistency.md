# 三层记忆一致性与容量维护

2026-10-09 批次 MEMFIX-20261009。前台回复、意图提示词与检索预算保持原有配置。

## 计分与重放

聊天使用和夜间维护共用 `lifecycle/value.py` 的指数衰减与滞回阈值，半衰期保持 240 天。
夜间任务只做衰减，不从初始 `importance` 覆盖累积 `current_score`，不给访问奖励。
身份 singleton 保留 L1；每日总结不能由使用奖励晋升为永久核心人设。

使用事件以持久化的用户消息 ID、owner、workspace 校验；消息必须属于同一工作区的有效会话，
工作区仍处于 active 状态。事件接受期限 7 天；凭据保留 30 天后分批清理。
相同消息、同侧、同记忆只奖励一次，候选升级为实际注入只补足差额。
凭据、分数、层级和升降级审计在同一事务提交。数据库作用域锁和有序行锁避免丢失并发奖励；
singleton 的最终写入也使用同一作用域锁，避免与生命周期晋升同时造出第二条 L1。
使用更新失败会记录 warning 并回滚，前台回复继续；夜间失败会进入 cron 健康记录。

## 来源与日常总结

`profile_seed`、`knowledge_seed` 的可信身份、偏好、思维事实可在 L2/L3 保留精确分类。
AI 自述和日常总结不得据此创建新的永久人设。原来的 Web 提示词版本和内容不改动。

日常回顾使用配置时区中昨日 `[00:00, 次日00:00)` 的已保存作息、调整、主动消息与游戏记录，
同时限定 owner、agent、workspace。不会把今天 Redis 作息当成昨天的经历，也不会扫描别人的摘要。
总结只存生活与情绪，固定为 L3，importance 不超过 0.49。
每工作区每日数据库唯一凭据防止双 worker 重复生成，拆分后最多新增 5 条。
缺少昨日作息时不补造经历。

失败尝试标为 failed，并禁止自动重跑，避免部分写入后重复造记忆。
进程在提交状态前退出时会保留 running。运维应先核对该日期的实际写入与日志，
再决定是否人工修复；不得直接删除凭据盲目重跑。

## 容量边界与恢复

自动日常总结在每工作区最多保留 2,000 条原始条目，包含已归档条目；到达预算后记录
`capacity_skipped`，停止添加此类可选总结。正常聊天的事实、提醒和可信人设不受此预算限制。
摘要簇本身不再参与递归压缩；原文永久保留，实际用户历史仍需常规存储扩容与备份。

压缩摘要先以归档状态写入，随后在同一事务校验原文/归属、记录审计、归档全部原文并发布摘要。
中途失败不会留下部分归档或可用的重复摘要。
夜间每侧最多清理 500 条已归档 L3 原文向量，仅限有同作用域审计且仍有有效摘要的条目，
排除可信种子。原文和审计不删；这部分向量属于可以重新生成的派生数据。
归档未成功的未发布摘要及其向量会撤销；进程崩溃留下的同类临时输出在一天后分批清理。
这只删除从未生效、没有任何原文归档审计指向的派生摘要，不删除原始记忆。

撤销脚本 `scripts/undo_consolidation.py` 默认 dry-run。
真正撤销时先重建所有原文向量，再将向量、取消原文归档、归档摘要和撤销审计一起提交。
模型不可用、维度错误或任一数据库写入失败时保持旧状态。清理任务使用行锁跳过恢复中的条目。
重新生成向量依赖嵌入服务，因此服务不可用时可以看原文，但不能完成检索恢复。

## 有界夜间维护与发布

每侧一次最多选择 1,000 个最久未维护的 ID，按 owner/workspace 分组后每事务最多处理 250 条；
不加载全量 L2 内容或向量。活跃聊天即时更新，其余条目由最旧优先的兜底扫描逐批维护。
日志始终输出 user、ai 两侧完成计数和 `engine=cumulative_decay_v2`。
零候选是合法结果，不能据此推断任务没跑，也不能只看 Redis ok 就声称维护已验收。

两条新增 Prisma migration 只扩展凭据表、索引，并为缺少衰减时钟的历史行补上线时刻；
不修改原文、初始重要度、累积分数或层级，已有时钟不重置。历史 migration 不修改。
新表与旧应用兼容；回滚应用时保留这些表，禁止重置或回滚删除生产数据库。
旧应用会恢复旧的夜间计分方式，因此应用回退是临时故障恢复措施，应尽快恢复修复版本。

发布资格包括真实 PostgreSQL 并发/重放/回滚、总结隔离/日期/预算、压缩恢复/清理竞态、
5 万合成行的维护资源测试、迁移升级与旧 client 兼容、完整 CI 和真实容器聊天/worker 测试。
提交前必须完成两轮 review。发布后核对迁移、提示词指纹、worker、健康状态与错误日志。
