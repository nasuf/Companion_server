# 活动推荐与旅途质量修复（2026-10-05）

## 原因与处理

| 问题 | 原因 | 修复 |
|---|---|---|
| 卡片与详情不同 | 展示不同文案字段、旧快照、接受同地点推荐时静默换活动 ID | 详情读取当前同一 ID，同时显示摘要与详情；同地点冲突明确返回 409 |
| 到达无核验 | 设备定位缺失仍放行 | 有地点坐标必须 GPS、精度 ≤100m、距离 ≤200m；WGS84 转 GCJ02 后计算；无坐标只能明确手动记录，标记未核验 |
| 感想重复 | 复用预生成文案和固定兜底，缺少最终入库去重 | 已发送历史注入、一次有限重试、文本近重复与照片指纹去重；数据库行锁保证跨 worker 最多三条 |
| 引导生硬 | 任务指令语气、机械要求看下一个目标 | Web 新版本约束短句、松弛、不催促，不暗示现场同行 |
| 回忆搬运介绍 | 推荐文案被当作旅途证据 | 仅使用到达至结束的用户原话、照片、语音，以及明确提交给该活动的完成感想 |
| 到达即虚构手札 | 无素材也生成或固定抒情兜底 | 无记录时不调用模型、不生成手札；失败退回用户原话，不补经历 |
| 推荐理由带链接 | prose 与来源字段混用 | prose 清理网址，来源保留为服务端溯源元数据；按产品反馈移除客户端来源操作 |
| 待出行不能删除 | 缺少删除 API 和客户端入口 | 本人未开始活动可软删除；删除与到达互斥，不能重新接受复活 |
| 图文错位、只有一张 | 忽略 Tavily 每条 result 的 images，类别泛搜、图库兜底、首图展示 | 多图解析；精确地点与城市绑定；页面封面/图片说明证据；下载后验证、去重、补位；详情相册 |

## 两个阶段

1. 保留 Tavily 做发现，检索具体地点页面；不把查询级混合图片或 LLM 编造 URL 分配给地点。最多两次精确补搜、每次最多十二个候选，目标三张。无可靠图片允许零张，不用风景图库凑数。保留来源元数据。
2. 新增独立公共地点目录与七天图片缓存，搜索结果缓存一小时；缓存不包含用户偏好、推荐理由或上传照片。带日期的活动必须有有效结束时间，过期不推荐。没有新增收费地图供应商。公共网页可访问不等于图片获得商用授权，后续需要按内容来源确定授权范围。

原生设备定位与本地距离计算不需要高德商用 Key；地点地理编码仍使用已有配置。没有可靠地点坐标时不会假装通过核验。设备 GPS 不是防作弊证明，真机权限与系统定位质量需要设备验收。

## 提示词发布

发布清单：`scripts/prompt_releases/20261005_offline_quality.json`，八个 key。
发布器：`scripts/publish_offline_quality_prompts.py`，默认只读，`--apply` 才保存。
发布前检查生产当前值 SHA、完整历史、占位符与渲染；调用 Web 相同的
`update_prompt_text(..., expected_updated_at=...)`；保留启用状态和默认值；
发布后核对 DB、Redis、manual_save 版本、历史不变及实际热读取。
不修改 registry defaults，不把 code_sync 当成 Web 保存。

真实生产模型候选提示词试跑发现：空素材时模型仍可能补写行为。因此“到达但无素材”必须由代码直接拒绝生成，不能仅靠提示词。

## 验证方式与边界

- `tests/test_offline_quality_e2e.py`：真实认证 HTTP、Postgres、Redis、Web 提示词发布、生命周期、权限、并发、真实记录窗口、手札拒绝与失败路径、历史图库修复。
- `tests/test_offline_gallery_quality.py`：来源绑定、多图片字段、下载失败补位、近重复、损坏图片、私网跳转、无关网页图片过滤。
- `OFFLINE_FLUTTER_E2E=1 pytest tests/test_offline_quality_e2e.py`：启动本地 API，通过相邻 Flutter 仓库真实 `CompanionApi` 发 HTTP，验证到达、归档、空手札拒绝和删除。
- Flutter `offline_journey_flow_test.dart`：相册滑动、来源操作不显示、手机宽度下同排页脚、手动到达确认、删除确认、禁用空手札。
- 后端 CI 质量集、Flutter analyzer、Prisma 迁移、Python 编译、diff 检查。

外部 Tavily、模型和通知在自动化 E2E 中使用可重复 fixture；真实模型另做候选输出检查。
没有向生产用户发送测试消息。自动化通过不代表真实网站永不改版或模型永不出错；未做手机真机 GPS、系统权限及外部浏览器验收。

## 上线及存量处理

先部署数据库迁移和服务，再发布提示词；Flutter 需安装包含本次提交的新构建。
`repair_offline_galleries.py` 默认只读；`--apply --backup <新路径>` 先保存只读快照，
再有界补搜、事务更新推荐图库及历史聊天卡片封面。无法验证的旧图撤下，保留空占位。
不处理用户上传素材，不删除文件；图库 CAS 避免覆盖并发修改。
回滚代码不应回滚用户数据或既有提示词历史，提示词回退应再发布一个版本。


## 2026-10-06 图片回归与删除语义修复

上次过度依赖二次请求来源 HTML。生产网络中部分百科、资讯页返回 403，
即使 Tavily 已抓到带说明的真实图片，也会被全量过滤。
活动搜索现在保留每个结果的 Markdown 正文及原生 alt/caption，直接复用图旁证据；
仍校验具体地点和城市，不采用查询级混合图片。图标、标识、设计效果图等排除，
纯页面标题不会自动赋予页面所有图片地点归属。下载仍保留公网地址、跳转、
类型、像素、大小及重复校验。不同来源交错尝试，缓存齐全时不再请求上游。
生产网络实测：镇江市图书馆、大岭山森林公园均取回并落盘 3 张；
万江绿道、荔香湿地公园的单次测试未找到可验证图片。照片覆盖率仍依赖具体来源，
不能以回填无关图达到表面上的 100%。

存量恢复使用 `--fill-only --apply --backup <新路径>`：只选空图库，有可靠图片才更新，
失败保留原记录；已有照片不动，聊天卡片封面与图库在同一事务内更新。
备份文件独占创建，图库更新继续使用 CAS。

删除入口为「出门小说明｜删除该活动」，只在未到达的有效活动显示。
「查看来源」「复制链接」两个入口已移除。

待出行是可撤销计划，不再把点击接受的合成文本另行抽取为长期记忆。
活动取消状态是事实源，取消同时撤销活动陪伴调度/领取状态。
聊天上下文和日常主动交流读取同用户、同工作空间最近 10 条取消记录，
含活动 ID、取消时间、无到达记录；取消原因和偏好变化保持未知。
只有取消记录时不再渲染「正在陪 TA 外出」模板；同地点的新活动仍独立有效。
保留原始聊天、已有真实经历及地点偏好，不依据地点名称批量删记忆。
该有界上下文不是对任意历史记忆的永久抹除，也不能保证 LLM 永远不误解旧对话。
本轮只改动态业务事实输入，未改 registry 提示词文案；已有 Web manual_save 版本保留。

定向验证覆盖：来源网页不可访问时使用已有图旁证据、标识/效果图排除、失败补位、
删除权限/幂等/到达并发、取消事实作用域、既有记忆保留、同地点新活动不受影响、
只补空图库、真实 Flutter HTTP 调用。外部模型/搜索在自动化 E2E 中仍使用 fixture，
生产网站可用性另做真实请求验证，不能混称全部是真实模型 E2E。

## 2026-10-06 具体场所与博物馆相册再次回归

生产记录显示，「镇江这些咖啡店」来自搜狐集合文章标题。旧兜底提取器把标题片段
当成地点，且兜底生成后绕过模型结果的完整校验。本轮统一模型与兜底的最终入口：
具体场所、同城市来源、近期去重、至少一张通过验证的照片全部满足才入库。
搜索来源窗口优先保留单个场所，保留括号中的分店名。无可靠配图时在 55 秒总预算内
最多尝试三个不同候选，全部失败则不创建空图卡片。仍以三张为目标，不承诺所有
具体场所都能找到三张，不用重复或无关图片凑数。

镇江博物馆的缺图原因是索引正文采用「图片外包 Markdown 链接，链接标题为图注」
的格式，旧解析器遗漏图注；相对图片路径也被忽略。新增链接图注、展陈场景与相对
路径解析，继续排除示意图、广告，并避免借用后面另一张图片的地点说明。
在生产网络使用候选解析器实测，取得三张不同的青铜、陶瓷、金银展厅照片；
实际文件已逐张目视核对，不是只检查 URL 数量。

存量一张图的相册可用 `--refill-incomplete --activity-id <指定ID>` 定向追加，
配合 `--apply --backup <新路径>` 发布。已有照片顺序保持，失败不删旧图；
不允许省略 ID 或混用全量模式，事务更新前再次检查取消/过期状态与原图库。
此轮不修改 registry 提示词，不需要发布新的提示词版本。

新增 HTTP + Postgres + Redis 回归覆盖：模型返回集合标题、具体咖啡店无图时换候选、
所有候选无图时不入库、不发卡片、博物馆三张图片在详情一致、指定相册追加且失败保留。
自动化仍以 fixture 替代外部搜索/模型/下载；实际生产网页照片验证另行完成。

## 2026-10-06 连续生成空结果的可用性修正

生产日志确认已进入生成阶段，定位和会话存在；失败链是搜索四篇文章就提前停止、
仅剩一个具体咖啡店、无可信图片被硬拒绝，连续重试又复用相同的搜索缓存。
上一节「至少一张图才入库」在本轮撤回：具体地点、同城市来源、去重和有效期仍是
必要条件，图片作为优先项；三个候选都缺图或图库超时，保留首个已核实的真实地点，
不保留模型编造的图片地址。仍优先选择有可信配图的候选，不放松图片归属校验。

搜索改为按四个不同、可用的具体场所决定提前停止（同地点多篇文章不重复计数）；
最多十二个查询，两路并行，40 秒总预算。类别定向搜索使用城市、单个类别、地址和
开放时间，不把咖啡偏好塞进每个类别。来源窗口先保留不同场所，城市名兼容「镇江」
与「镇江市」。模型从文章识别出的店名如尚未有地点来源，最多一次定向检索验证，
验证成功后由新来源重建地点事实，不把旧文章推测的地址/设施挂到新来源上。

手动生成失败返回结构化 reason/message：活动关闭、缺少会话、缺少城市、没有合适
候选各自区分。计划任务继续静默跳过。Flutter 沿用结构化错误展示，兼容旧服务的
null 提示也改为中性措辞，不再无依据指向定位授权。真实 Flutter HTTP E2E 覆盖
候选不足的 503 文案，并继续完成原到达/归档/删除链路。

定向回归涵盖文章数量不等于地点数量、城市后缀、无图/超时可用性、独立地点来源、
异城来源拒绝、四种失败原因以及不写库/不发消息。生产网络候选代码试跑（加载生产
运行配置，未创建推荐或发送消息）得到来源匹配的镇江市图书馆，三张图片。
